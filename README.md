# anum_parser

Отдельный экспериментальный репозиторий для сериализации, десериализации и визуализации ачисел.

## Зачем он нужен

Теория ачисел содержит несколько исторических и новых вариантов чтения одной физической записи. Здесь они реализуются как независимые алгоритмы и проверяются на общем наборе примеров.

Успешный эксперимент сам по себе не изменяет нормативное описание МТС. Принятый результат переносится в `anum_docs` отдельным изменением после проверки.

## Главное различение

Лаборатория никогда не называет одним словом следующие представления:

1. последовательность исходных символов;
2. последовательность абитов;
3. связь;
4. упорядоченная последовательность ссылок на связи;
5. акорневая связь-последовательность, используемая как носитель;
6. связь, хранящая ачисло;
7. денотат, полученный конкретной десериализацией.

Для МТС действует базовая аксиома тождества связи:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

То есть связь полностью определяется началом и концом. Две различные связи с одинаковыми полюсами в МТС невозможны. Технические `id` в лабораторных файлах являются только адресами записей, а не дополнительным уровнем тождества.

Это принципиально отличает используемую здесь модель МТС от модели сети дуплетов Теории связей, где отдельная ссылка связи и значение пары являются разными уровнями.

## Форматы

- `.anum4` — исходное четверичное ачисло профиля `[ ] 1 0`;
- `.anums` — исходное строковое ачисло в UTF-8 без скрытой нормализации;
- `.anum.json` — самодокументируемый контейнер эксперимента;
- `.aset.json` — наглядный снимок канонической асети и связанных представлений.

Подробно: [`docs/formats.md`](docs/formats.md).

## Веб-лаборатория

Статическое приложение позволяет:

- вводить или загружать разные форматы;
- независимо выбирать десериализатор и сериализатор;
- сравнивать два десериализатора на одном исходнике;
- отдельно видеть символы, абиты, последовательности ссылок, акорневые цепочки и связи-хранилища;
- смотреть пошаговую трассу стека и текущего указателя;
- визуализировать асеть в интерактивном графе с перемещением, масштабированием и несколькими раскладками;
- сохранять `.aset.json` и без потерь восстанавливать исходную запись, когда это доказано происхождением данных.

Приложение не требует сервера и предназначено для публикации через GitHub Pages.

## Первые десериализаторы

- `string-flat-v0` — строковая левая свёртка;
- `abit-flat-v0` — контрольный вариант без специального смысла скобок;
- `stack-group-value-v0` — группа возвращает значение;
- `stack-root-wrap-v0` — непустой результат группы оборачивается связью от акорня.

Последние два варианта имеют статус **экспериментальных стратегий закрытия**. Наличие кода не делает их аксиомами МТС.

## Первые сериализаторы

- `aset-json-v0` — сохранить лабораторную `.aset.json`;
- `source-replay-v0` — без потерь вернуть исходное `.anum4` или `.anums` при наличии свидетельства происхождения;
- `source-envelope-v0` — сохранить тот же источник в `.anum.json`.

Лаборатория не предполагает, что произвольную асеть можно автоматически и однозначно сериализовать в ачисло.

## Корпус тестов

[`examples/cases.json`](examples/cases.json) содержит успешные и ошибочные физические входы: пустые и вложенные контексты, соседние группы, группы внутри последовательностей, разные стратегии закрытия, исторические строки, Unicode и запрещённые символы `.anum4`.

Каждый элемент корпуса исполняется как отдельный Node-тест. Поэтому изменение алгоритма показывает конкретные входы, на которых изменилось поведение.

Отдельные тесты проверяют фундаментальный инвариант: повторное получение одной пары `(start,end)` возвращает ту же связь, а импорт `.aset.json` с двумя разными `id` одной формы отвергается.

## Локальная проверка

Требуется Node.js 24 или новее.

```bash
npm run check
npm test
```

## Управление изменениями

Изменения проходят обязательную проверку `repo-guard`.

Каждый PR должен явно ограничивать область изменения.

`ChangeIntent` описывает обычное изменение.

`GovernanceGrant` требуется для изменения политики и других управляющих файлов.
