# Архитектура лаборатории

`anum_parser` строится как маленький статический стенд. Главная задача — делать различия видимыми и сравнивать конкурирующие алгоритмы на одинаковом входе.

## Слои

```text
raw bytes / textarea
        ↓
format reader
        ↓
symbol sequence
        ↓
lexical profile / dictionary
        ↓
abit or exact-ref sequence
        ↓
deserializer variant
        ↓
exact link network + trace
        ↓
views / SVG / export
```

## Шесть представлений

### 1. Последовательность символов

Физический/лексический уровень. Для `.anums` это Unicode scalar values; для `.anum4` — четыре ASCII-знака.

### 2. Последовательность абитов

Результат явного профиля разрешения `[ ] 1 0`. Даже при физическом совпадении с source symbols это отдельное представление.

### 3. Связь

Exact occurrence с собственным `id`, `start`, `end`. Равенство полюсов не означает тождество occurrence.

### 4. Последовательность связей

Упорядоченный список exact refs. Список не является связью и не должен материализовываться молча.

### 5. Акорневая связь-последовательность

Конкретный carrier, построенный как left fold с `∞` в роли физического начального носителя:

```text
R -> v1
(R -> v1) -> v2
...
```

### 6. Связь, хранящая ачисло

Отдельная exact связь, создаваемая только конкретным serializer profile. Она не равна carrier или denotation по умолчанию.

## Exact refs для символов в лаборатории

Для закрытого наглядного `.aset.json` каждому разрешённому символу/абиту создаётся отдельная exact occurrence. В версии `0.1` такие лабораторные occurrences могут иметь те же полюса `R -> R`, но остаются occurrence-различными и помечаются `symbol-occurrence`/`abit-occurrence`.

Это **технический способ дать символу exact ref в экспериментальной сети**, а не нормативное определение символов МТС. Distinguished root определяется полем `root`, а не только формой полюсов.

## Deserializer registry

Каждый алгоритм имеет:

```js
{
  id,
  title,
  status,
  inputKinds,
  deserialize(source, options)
}
```

Статус обязателен:

- `historical`;
- `experimental`;
- `accepted`;
- `rejected`.

UI не имеет понятия «алгоритм по умолчанию = истина». Он лишь выбирает начальный эксперимент.

## Первые варианты

### `string-flat-v0`

Строковые Unicode-символы разрешаются в exact symbol occurrences. Денотат — left fold без акорня как операнда непустой смысловой последовательности. Отдельно строится root-chain carrier.

### `abit-flat-v0`

Все `[ ] 1 0` рассматриваются как четыре значения и сворачиваются слева. Никакой стековой семантики.

Нужен как baseline/контрпример.

### `stack-group-value-v0`

- `[` — открыть frame;
- новый frame начинается пустым, его пустой результат — distinguished `R`;
- `1/0` — значения текущего frame;
- `]` — закрыть frame и передать его результат как одно значение родителю;
- left fold непустого frame начинается с первого значения, не с `R`.

Это **экспериментальная** стратегия закрытия. Она удобна для проверки гипотезы «группа возвращает значение».

### `stack-root-wrap-v0`

Как предыдущий вариант, но при закрытии непустого frame внутренний результат сначала оборачивается одной связью `R -> inner`. Пустой frame возвращает exact root.

Это отдельный эксперимент для проверки carrier-like трактовки вложенности.

## Trace

Каждый десериализатор возвращает пошаговую трассу:

```js
{
  step,
  token,
  operation,
  depth,
  current,
  values,
  producedLinks,
  note
}
```

Trace — отладочное свидетельство алгоритма. Он не является новой онтологией МТС.

## Сериализаторы

Первый обязательный serializer — `source-replay-v0`: если `.aset.json` содержит provenance исходного raw artifact, UI может вернуть его без потерь.

Дополнительно `storage-link-v0` может экспериментально создать отдельную exact связь:

```text
storageLink = carrier -> denotation
```

Такая топология **не является принятым законом**, а существует для воспроизведения исторической идеи «связь, кодирующая ачисло».

## Визуализация

SVG представляет **связи как узлы визуализации**, потому что в асети сама связь является адресуемой сущностью.

Для каждой exact связи `L` рисуются два отношения:

```text
L --start--> start(L)
L --end----> end(L)
```

Это не превращает МТС в обычный граф «узлы+рёбра»; SVG — лишь интерфейс к таблице exact links.

## GitHub Pages

Приложение не требует backend или framework:

```text
index.html
styles.css
src/*.js
```

ES modules работают непосредственно из статических файлов GitHub Pages. Node нужен только CI-тестам.

## Граница с `anum_docs`

Эксперимент считается кандидатом на перенос только если:

1. алгоритм имеет устойчивый id;
2. corpus зелёный;
3. контрпримеры перечислены;
4. известны source/topology/semantic round-trip свойства;
5. принято отдельное решение в `anum_docs`.

До этого всё остаётся локальной моделью `anum_parser`.
