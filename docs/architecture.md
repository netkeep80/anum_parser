# Архитектура лаборатории

`anum_parser` строится как маленький статический стенд. Главная задача — делать различия видимыми и сравнивать конкурирующие алгоритмы на одинаковом входе.

## Слои

```text
исходные байты / поле ввода
        ↓
чтение формата
        ↓
последовательность символов
        ↓
лексический профиль / словарь
        ↓
абиты или точные ссылки
        ↓
выбранный десериализатор
        ↓
точная сеть связей + трасса
        ↓
выбранный сериализатор / визуализация
```

## Шесть представлений

### 1. Последовательность символов

Физический/лексический уровень. Для `.anums` это Unicode-символы; для `.anum4` — четыре ASCII-знака.

### 2. Последовательность абитов

Результат явного профиля разрешения `[ ] 1 0`. Даже при физическом совпадении с исходными символами это отдельное представление.

### 3. Связь

Точное вхождение с собственным `id`, `start`, `end`. Равенство полюсов не означает тождества вхождений.

### 4. Последовательность связей

Упорядоченный список точных ссылок. Список не является связью и не должен материализовываться молча.

### 5. Акорневая связь-последовательность

Конкретный носитель, построенный как свёртка с `∞` в роли физического начального носителя:

```text
R -> v1
(R -> v1) -> v2
...
```

### 6. Связь, хранящая ачисло

Отдельная точная связь, создаваемая только конкретным профилем эксперимента. Она не равна носителю или денотату по умолчанию.

## Точные ссылки для символов в лаборатории

Для замкнутого наглядного `.aset.json` каждому разрешённому символу/абиту создаётся отдельное точное вхождение. В версии `0.1` такие лабораторные вхождения могут иметь те же полюса `R -> R`, но остаются различными по `id` и помечаются `symbol-occurrence`/`abit-occurrence`.

Это **технический способ дать символу точную ссылку в экспериментальной сети**, а не нормативное определение символов МТС. Выделенный акорень определяется полем `root`, а не только формой полюсов.

## Реестр десериализаторов

Каждый алгоритм имеет:

```js
{
  id,
  title,
  status,
  inputKinds,
  deserialize(source, options)
}
```

Статус обязателен:

- `historical`;
- `experimental`;
- `accepted`;
- `rejected`.

Интерфейс не предполагает, что выбранный первым алгоритм является истинным. Это только начальный эксперимент.

## Первые варианты десериализации

### `string-flat-v0`

Строковые Unicode-символы разрешаются в точные вхождения. Денотат — левая свёртка без акорня как операнда непустой смысловой последовательности. Отдельно строится акорневой носитель.

### `abit-flat-v0`

Все `[ ] 1 0` рассматриваются как четыре значения и сворачиваются слева. Никакой стековой семантики.

Нужен как контрольный контрпример.

### `stack-group-value-v0`

- `[` — открыть кадр;
- новый кадр начинается пустым, его пустой результат — выделенный `R`;
- `1/0` — значения текущего кадра;
- `]` — закрыть кадр и передать его результат как одно значение родителю;
- левая свёртка непустого кадра начинается с первого значения, не с `R`.

Это **экспериментальная** стратегия закрытия. Она проверяет гипотезу «группа возвращает значение».

### `stack-root-wrap-v0`

Как предыдущий вариант, но при закрытии непустого кадра внутренний результат сначала оборачивается одной связью `R -> inner`. Пустой кадр возвращает точный акорень.

Это отдельный эксперимент для проверки трактовки вложенности через акорневой носитель.

## Трасса

Каждый десериализатор возвращает пошаговую трассу:

```js
{
  step,
  token,
  operation,
  depth,
  current,
  values,
  producedLinks,
  note
}
```

Трасса — отладочное свидетельство алгоритма. Она не является новой онтологией МТС.

## Реестр сериализаторов

Сериализатор выбирается **отдельно** от входного формата и десериализатора. Наличие асети само по себе не означает, что из неё можно однозначно получить четверичное или строковое ачисло.

Первый реестр содержит:

- `aset-json-v0` — точное сохранение лабораторной `.aset.json`;
- `source-replay-v0` — без потерь вернуть исходные `.anum4`/`.anums`, только если `provenance.source` это доказывает;
- `source-envelope-v0` — сохранить тот же физический источник в `.anum.json`.

Интерфейс сериализатора:

```js
{
  id,
  title,
  status,
  supports(aset),
  serialize(aset)
}
```

Если доказуемого обратного преобразования нет, соответствующий сериализатор не предлагается.

Отдельно `storage-link-v0` остаётся экспериментальной **топологией хранения**, а не файловым сериализатором:

```text
storageLink = carrier -> denotation
```

Такая связь существует только по явной команде эксперимента и не является принятым законом МТС.

## Корпус экспериментов

`examples/cases.json` — единый набор физических входов. Каждый случай имеет устойчивый `id`, исходный формат, данные, выбранный алгоритм и при необходимости ожидаемый код ошибки.

Node-тесты разворачивают каждый элемент корпуса в отдельный тест. Поэтому изменение стратегии закрытия показывает не просто «suite красный», а конкретные входы, на которых изменилось поведение.

Корпус содержит:

- пустые и одноэлементные последовательности;
- пустые, соседние и глубоко вложенные контексты;
- группы в начале, середине и конце последовательности;
- две конкурирующие стратегии закрытия;
- непарные и лишние скобки;
- запрещённые символы `.anum4`;
- исторические строковые примеры;
- кириллицу, emoji, NFC/NFD и переводы строк.

## Визуализация

SVG представляет **связи как узлы визуализации**, потому что в асети сама связь является адресуемой сущностью.

Для каждой точной связи `L` рисуются два отношения:

```text
L --start--> start(L)
L --end----> end(L)
```

Это не превращает МТС в обычный граф «узлы+рёбра»; SVG — лишь интерфейс к таблице точных связей.

## GitHub Pages

Приложение не требует сервера или фреймворка:

```text
index.html
styles.css
src/*.js
```

Модули ES работают непосредственно из статических файлов GitHub Pages. Node нужен только проверкам CI.

## Граница с `anum_docs`

Эксперимент считается кандидатом на перенос только если:

1. алгоритм имеет устойчивый `id`;
2. корпус зелёный;
3. контрпримеры перечислены;
4. известны свойства восстановления исходника, топологии и семантики;
5. принято отдельное решение в `anum_docs`.

До этого всё остаётся локальной моделью `anum_parser`.
